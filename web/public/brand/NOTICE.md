# 브랜드 자산의 출처와 가공 내역

여기 있는 마크·워드마크는 **누띠 자사 자산**입니다(폰트와 달리 제3자 저작물이
아닙니다 — `public/fonts/NOTICE.md` 는 별건입니다). 그래도 출처를 적어 두는
이유는, 어느 것이 원본이고 어디를 우리가 손댔는지가 나중에 로고가 바뀔 때
유일한 판단 근거가 되기 때문입니다.

색·서체와 마찬가지로 **본체는 쇼핑몰입니다**. 브랜드 자산을 규정한 문서가
어디에도 없어서 `nutti.co.kr` 에서 직접 받아 왔습니다(2026-08-05 실측).
지어내지 않았습니다.

| 파일 | 원본 | 원본 크기 |
| --- | --- | --- |
| `favicon-32.png`<br>`favicon-180.png`<br>`favicon-512.png` | 쇼핑몰 `<link rel=icon>` 이 가리키는 `favicon-{32,180,512}.png` | 그대로 |
| `nutti-wordmark.svg` | 쇼핑몰 헤더 로고 `..._top.jpg` (확장자만 jpg 이고 실제로는 5760×1736 PNG) | 5760×1736 |

## 파비콘 — 왜 PNG 세트인가

원본이 **래스터**입니다. 512 조차 작은 원본을 업스케일한 것이라 경계가 흐릿한데,
이걸 벡터로 트레이싱하면 원본에 없는 선명함이 생깁니다. 그건 마크를 우리가 고쳐
그리는 것이고, 그러면 쇼핑몰의 파비콘과 앱의 파비콘이 서로 다른 그림이 됩니다.
흐릿함째로 원본을 씁니다.

손댄 것은 **팔레트 양자화 하나**뿐입니다(FASTOCTREE 32색). 512 가 131KB →
14KB 가 됐고, 픽셀 최대 오차는 29/255 로 전부 안티에일리어싱 경계에서 납니다.
형태·색은 그대로입니다.

`favicon-180.png` 는 iOS 홈 화면 아이콘이면서 **W-02 앱바의 마크로도 재사용**
합니다. 24px 로 쓰기엔 큰 파일이지만 파비콘으로 이미 받는 파일이라 요청이 늘지
않습니다. 24px 전용 파일을 따로 두면 같은 그림이 두 벌이 됩니다.

## 워드마크 — 왜 SVG 인가

이쪽은 반대로 **2색 단색 실루엣**이라 벡터가 원형입니다. 원본 PNG(92KB)를
헤더에서 쓸 크기로 줄이면 확대에 못 견디고, 그대로 쓰면 14px 로 표시할 그림에
92KB 를 씁니다.

색별 알파 마스크를 경계 추적한 뒤 Douglas-Peucker 로 단순화했습니다(작업 해상도
1600px, 허용 오차 0.7px). 결과를 다시 래스터화해 원본과 대조한 IoU 는
브라운 **0.9876** / 세이지 **0.9885** 이고, 차이는 전부 경계 1px 안티에일리어싱
입니다. 루프 개수도 예상과 맞습니다 — 브라운 4개(N·U·T·T), 세이지 2개(i 의 몸통과
점). 구멍이 없는 글자들이라 `fill-rule` 이 필요 없습니다.

9.8KB 이고 gzip 후 약 3KB 입니다.

## 로고의 실제 색

**로고는 `#8C6239` 입니다.** `src/index.css` 에서 `--color-brand-2` 로 잡아 둔
그 값이고, `--color-brand`(`#5C3D24`)가 아닙니다. `i` 는 브라운이 아니라
**세이지 그린 `#6D7E5A`** 이며, 토큰에는 없는 색입니다 — 로고 안에서만 쓰이고
UI 색으로는 쓰이지 않아서 일부러 토큰으로 올리지 않았습니다.

두 값 모두 원본 PNG 픽셀 집계로 확인했습니다(브라운 90.0% / 세이지 9.9%,
나머지 0.1% 는 경계 픽셀).

## 바꿀 때

쇼핑몰 로고가 바뀌면 여기도 바뀌어야 합니다. 워드마크는 위 절차(마스크 →
경계 추적 → 단순화 → IoU 대조)를 다시 밟으세요. 눈으로만 보고 넘기면 색이
한 단계 어긋난 것을 못 잡습니다.
