# 브랜드 자산의 출처와 가공 내역

여기 있는 파일은 **두 종류**입니다. 누띠 마크·워드마크는 자사 자산이고(폰트와
달리 제3자 저작물이 아닙니다 — `public/fonts/NOTICE.md` 는 별건입니다),
`kakao-symbol.png` 와 `naver-symbol.svg` 는 **제3자 상표**라 쓰는 규칙이
따로 있습니다(아래 「소셜 로그인 심볼」).

출처를 적어 두는 이유는 어느 것이 원본이고 어디를 우리가 손댔는지가 나중에
로고가 바뀔 때 유일한 판단 근거가 되기 때문입니다.

자사 자산은 색·서체와 마찬가지로 **본체가 쇼핑몰입니다**. 브랜드 자산을 규정한
문서가 어디에도 없어서 `nutti.co.kr` 에서 직접 받아 왔습니다(2026-08-05 실측).
지어내지 않았습니다.

| 파일 | 원본 | 원본 크기 |
| --- | --- | --- |
| `favicon-32.png`<br>`favicon-180.png`<br>`favicon-512.png` | 쇼핑몰 `<link rel=icon>` 이 가리키는 `favicon-{32,180,512}.png` | 그대로 |
| `nutti-wordmark.svg` | 쇼핑몰 헤더 로고 `..._top.jpg` (확장자만 jpg 이고 실제로는 5760×1736 PNG) | 5760×1736 |
| `kakao-symbol.png` | 카카오 공식 로그인 버튼 `kakao_login_large_wide.png` (600×90) 에서 잘라 냄 | 36×34 |
| `naver-symbol.svg` | 네이버 공식 로그인 버튼 애셋 `NAVER_login_KR.ai` 의 N 로고 벡터 | 16×16 |

## 파비콘 — 왜 PNG 세트인가

원본이 **래스터**입니다. 512 조차 작은 원본을 업스케일한 것이라 경계가 흐릿한데,
이걸 벡터로 트레이싱하면 원본에 없는 선명함이 생깁니다. 그건 마크를 우리가 고쳐
그리는 것이고, 그러면 쇼핑몰의 파비콘과 앱의 파비콘이 서로 다른 그림이 됩니다.
흐릿함째로 원본을 씁니다.

손댄 것은 **팔레트 양자화 하나**뿐입니다(FASTOCTREE 32색). 512 가 131KB →
14KB 가 됐고, 픽셀 최대 오차는 29/255 로 전부 안티에일리어싱 경계에서 납니다.
형태·색은 그대로입니다.

`favicon-180.png` 는 iOS 홈 화면 아이콘이면서 **W-02 앱바의 마크로도 재사용**
합니다. 24px 로 쓰기엔 큰 파일이지만 파비콘으로 이미 받는 파일이라 요청이 늘지
않습니다. 24px 전용 파일을 따로 두면 같은 그림이 두 벌이 됩니다.

## 워드마크 — 왜 SVG 인가

이쪽은 반대로 **2색 단색 실루엣**이라 벡터가 원형입니다. 원본 PNG(92KB)를
헤더에서 쓸 크기로 줄이면 확대에 못 견디고, 그대로 쓰면 14px 로 표시할 그림에
92KB 를 씁니다.

색별 알파 마스크를 경계 추적한 뒤 Douglas-Peucker 로 단순화했습니다(작업 해상도
1600px, 허용 오차 0.7px). 결과를 다시 래스터화해 원본과 대조한 IoU 는
브라운 **0.9876** / 세이지 **0.9885** 이고, 차이는 전부 경계 1px 안티에일리어싱
입니다. 루프 개수도 예상과 맞습니다 — 브라운 4개(N·U·T·T), 세이지 2개(i 의 몸통과
점). 구멍이 없는 글자들이라 `fill-rule` 이 필요 없습니다.

9.8KB 이고 gzip 후 약 3KB 입니다.

## 로고의 실제 색

**로고는 `#8C6239` 입니다.** `src/index.css` 에서 `--color-brand-2` 로 잡아 둔
그 값이고, `--color-brand`(`#5C3D24`)가 아닙니다. `i` 는 브라운이 아니라
**세이지 그린 `#6D7E5A`** 이며, 토큰에는 없는 색입니다 — 로고 안에서만 쓰이고
UI 색으로는 쓰이지 않아서 일부러 토큰으로 올리지 않았습니다.

두 값 모두 원본 PNG 픽셀 집계로 확인했습니다(브라운 90.0% / 세이지 9.9%,
나머지 0.1% 는 경계 픽셀).

## 소셜 로그인 심볼 — 카카오 · 네이버

여기부터는 **남의 상표**입니다. 위 자사 자산과 규칙이 정반대예요 — 저쪽은 우리가
줄이고 다듬을 수 있지만, 이쪽은 **형태·비율·색을 바꾸는 것이 금지**입니다.
그래서 둘 다 각 사가 배포하는 파일에서 가져왔고, 비슷하게 그리지 않았습니다.

- 카카오 로그인 디자인 가이드 — <https://developers.kakao.com/docs/latest/ko/kakaologin/design-guide>
- 네이버 로그인 BI 가이드 — <https://developers.naver.com/docs/login/bi/bi.md>

둘 다 **심볼이 필수**입니다. 카카오는 「심볼 없이 카카오 로그인 버튼을 구성할 수
없습니다」라고 못 박아 두었고, 그 전까지 우리 버튼에는 심볼이 없었습니다.

### 카카오 — 왜 PNG 를 «잘라» 쓰나

카카오는 **공개 벡터를 주지 않습니다.** 원본으로 제공되는 PSD 는 개발자 콘솔
로그인 뒤 [도구] > [리소스 다운로드] 안에 있고, 열려 있는 건 완성된 버튼 PNG
뿐입니다. 우리 버튼은 폭이 화면을 꽉 채우고 레이블도 우리 문구라 버튼 이미지를
통째로 쓸 수 없어서, 가이드가 허용하는 **재구성**(컨테이너+심볼+레이블을 우리가
조립)을 택했고 심볼만 필요했습니다.

`kakao_login_large_wide.png`(600×90, 표준 버튼의 2배)에서 검정 픽셀의 경계 상자
`x 29..64 · y 28..61` 을 그대로 잘랐습니다(36×34, 686B). **픽셀 가공은 없습니다** —
자른 뒤 저장한 파일과 원본 크롭의 픽셀 차이가 0 입니다.

배경(`#FEE500`)을 투명으로 빼지 않고 **노란 사각형째로** 둡니다. 우리 버튼 배경이
규정상 같은 `#FEE500` 이라 이음매가 보이지 않고, 알파를 만들어 내려면 색을 키잉해야
하는데 그건 「색을 바꾸지 말라」는 규정에 손을 대는 일입니다. 버튼의
`hover:brightness-95` 는 심볼과 배경에 똑같이 걸려서 같이 움직입니다.

18px 로 표시하므로 2배 자산입니다. 3배 화면에서는 조금 무르지만 카카오가 공개로
주는 것 중에는 이게 가장 큽니다.

### 네이버 — 왜 SVG 인가

이쪽은 **벡터 원본이 공개**입니다. `NAVER_login_KR.ai`(PDF 1.5)의 콘텐츠 스트림에서
N 로고 패스를 그대로 꺼냈습니다 — 정점 10개, 곡선 없음, 20/18/16 세 크기가 들어
있고 전부 정사각입니다. 16 짜리를 써서 `viewBox="0 0 16 16"` 로 정규화했습니다
(원본은 y 축이 위로 가는 PDF 좌표라 뒤집었습니다). 좌표 반올림 말고는 손댄 것이
없습니다.

공식 아이콘 PNG(`NAVER_login_Light_KR_green_icon_H56.png`)와 겹쳐 보고 형태가
같은 것을 확인했습니다.

### 색 — `#03C75A` 는 옛 스펙입니다

네이버 가이드의 「지정 컬러」 표가 지금 규정하는 값은 배경 `#03A94D`, 로고·레이블
`#FFFFFF` 입니다(2025-12 개정 애셋 기준). 오래 알려진 `#03C75A` 가 아닙니다 —
`screens/AccountSheet.tsx` 가 그 값을 쓰고 있었고 이번에 고쳤습니다.

카카오는 컨테이너 `#FEE500` 이고, 레이블은 **`#191919`** 를 씁니다. 가이드 본문은
「`#000000` 85%」라고 적는데 카카오가 실제로 내려주는 버튼 PNG 의 레이블 픽셀은
`#191919` 라 둘이 어긋납니다. 우리는 **그 PNG 에서 심볼을 잘라 쓰므로** 같은 파일의
값으로 맞췄습니다 — 안 그러면 한 버튼 안에서 심볼만 더 진해 보입니다.

### 바꿀 때

두 회사 중 한쪽이 BI 를 개정하면 애셋과 색을 **같이** 다시 받으세요. 이번에
`#03C75A` 가 낡은 채로 남아 있던 것이 그 예입니다 — 심볼을 안 쓰고 있어서 가이드를
다시 볼 계기가 없었습니다.

## 바꿀 때 (자사 자산)

쇼핑몰 로고가 바뀌면 여기도 바뀌어야 합니다. 워드마크는 위 절차(마스크 →
경계 추적 → 단순화 → IoU 대조)를 다시 밟으세요. 눈으로만 보고 넘기면 색이
한 단계 어긋난 것을 못 잡습니다.
