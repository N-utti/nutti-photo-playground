## 사파리 (2026-09-04)

### 기록거리 1 — 로그인 화면 입력칸 포커스 시 페이지가 확대되고, 그 상태가 이후 화면까지 남는다

- 확대는 로그인 뒤 홈·보관함·결과 화면(W-06)까지 그대로 유지된다. SPA 이동으로는 안 풀리고 **새로 고침으로도 안 풀린다.** 새 주소로 다시 들어가야 풀린다.
- 결과: 화면 오른쪽이 잘린다. 하단 탭 「누띠샵」, 상단 크레딧 표시가 화면 밖으로 나가고, 보관함 3열 격자의 세 번째 열이 반쯤 잘린다.
- 사생활 보호 모드·일반 모드 둘 다 재현. 인스타·네이버 인앱에서도 그대로 재현된다.
- 스크린샷: `s4-03.png`(확대된 로그인 화면), `s4-05.png`(확대 남은 홈), `s4-06-library.png`(잘린 보관함)

- W-06 「이미지 저장」: iOS 공유 시트가 열리고 JPEG 파일이 실린다(파일명 `nutti-<uuid>.jpg`, 330KB). 시트에서 「이미지 저장」을 고르면 사진 앱에 `IMG_2127.JPG`가 생겼다.

### 철회 — 새 탭에서 열면 로그인이 풀리는 현상

## 카카오톡 인앱 (2026-09-04, 카카오톡 26.7.3)

진입: 「나와의 채팅」에 링크를 보내고 탭. 인앱 브라우저에서 사이트가 **카카오 계정(수연)으로 이미 로그인된 상태**로 열렸다. 그래서 테스터 계정 대신 이 계정의 보관함(크레딧 5)으로 저장을 밟았다. 저장은 크레딧을 쓰지 않는다.

### 기록거리 2 — 「공유」가 카카오 공유 카드가 아니라 iOS 공유 시트에 링크를 싣는다

- W-06 「공유」를 누르면 iOS 공유 시트가 열리고, 실리는 건 이미지가 아니라 사이트 링크(제목 「누띠 사진 놀이터」, `play.nutti.co.kr`)다.
- 사파리에서는 같은 버튼이 JPEG 파일을 실었다. 카톡 인앱에서만 링크로 바뀐다.
- 스크린샷: `k-11-share.png`
- **고침 ②** — 아래 참고. 기기 재확인 필요.
- **카카오 공유 카드가 안 뜬 것은 버그가 아니다.** 카드는 OS 시트가 없는 곳(안드로이드 웹뷰·데스크톱)에서 자체 시트로 물러날 때만 그린다(`app/ShareFallbackSheet.tsx`). 아이폰 카톡은 시트가 있으므로 시트로 가는 게 설계대로다 — 「버튼은 어디서나 같고 갈리는 건 누른 뒤뿐」(2026-09-03 결정).

### 확인 결과 — 저장 동작 (통과, 체크리스트 전제와 다름)

- 체크리스트는 「카톡 웹뷰엔 `navigator.share`가 없고 blob 다운로드를 버린다」고 전제했는데, 이 버전의 카톡 웹뷰는 **파일을 실은 `navigator.share`가 동작한다.** 「이미지 저장」을 누르면 사파리와 똑같이 iOS 공유 시트가 열리고 JPEG(285KB)가 실린다.
- 시트에서 「이미지 저장」 → `IMG_2131.JPG` 생김. 첨부 주소(`download_url`) 이동 경로는 이 기기에서는 타지 않는다.
- W-09 일괄 저장 3장 → 시트 「3개의 이미지 저장」 → `IMG_2132~2134` 생김.
- 「N장 다운로드를 시작했어요」 토스트는 보이지 않았다. 「저장 중…」 버튼 상태만 봤다.
- 스크린샷: `k-07-save-1.png`, `k-13-batch-sheet.png`
- **그래서 안드로이드 웹뷰 경로는 이번 회차에서 검증된 게 아니다.** 첨부-주소 저장이 실제로 파일을 남기는지는 안드로이드 기기로 따로 밟아야 한다. `app/inAppBrowser.ts` 주석은 처음부터 두 플랫폼을 갈라 놨고, 체크리스트 본문만 안드로이드 이야기를 iOS 에 옮겨 적어 놨었다(체크리스트에 정정을 달아 뒀다).

### 닫힘 — 사이트 헤더가 처음부터 「진수연님」으로 뜨는 것

- 코드로 확인했다. 카카오 로그인은 버튼으로 시작하는 OAuth 뿐이고(`screens/AccountSheet.tsx`·`screens/AuthCallback.tsx`) 자동 로그인 경로가 없다. 카톡 인앱 브라우저가 저장소를 유지해서 **이전에 카카오로 로그인한 세션이 남아 있던 것**이다. 고칠 것 없음.
- 인앱 상단의 카카오 노란 버튼(카카오톡으로 공유)은 인앱 브라우저 자체 기능이라 사이트 코드와 무관.

## 고친 것 (코드)

### ① 자동 확대 — `src/index.css`

손가락이 주 입력인 기기(`pointer: coarse`)에서 글자를 넣는 칸의 글씨를 `max(1rem, 16px)`
로 깐다. 확대를 **막는** 게 아니라 확대할 이유를 없애는 쪽이다. viewport 의
`maximum-scale=1` 은 손가락 확대까지 같이 막아서(WCAG 2.2 1.4.4) 쓰지 않았다.
`@layer` 밖에 둔 것은 이 규칙이 화면의 `text-sm` 을 이겨야 해서다.

**테스트 없음.** jsdom 은 스타일시트의 미디어 쿼리를 적용하지 않아, 써 봐야 「규칙이
파일에 있다」만 확인하고 확대가 사라지는지는 못 본다. → 기기 재확인 필요.

### ② 카톡 공유 — `src/screens/W06Result.tsx`

원인은 실측 두 줄이 **변수 하나짜리 비교**였던 데서 나왔다. 같은 화면에서 「이미지
저장」(파일만)은 JPEG 285KB 가 실렸고, 바로 이어 누른 「공유」(파일+문구)는 링크가
실렸다. 코드가 받아 둔 파일을 탭 사이에 물고 있어 **파일은 같은 것**이고 달라진 건
`text` 하나뿐이다. 사파리·네이버는 같은 payload 로 사진이 그대로 실렸다.
→ 카톡 웹뷰에서만 문구를 빼고 파일만 넘긴다.

테스트를 박았고, 문구를 되살리면 그 테스트가 빨간불이 되는 것까지 확인했다.
다만 카톡 시트가 실제로 사진을 받아 주는지는 기기 밖에서 알 수 없다. → 기기 재확인 필요.

### ③ 저장 뒤 안내 없음 — `W06Result.tsx` · `W09Library.tsx`

데스크톱(`opened`)·웹뷰(`downloadCount`)·만료·실패 갈래에는 전부 문구가 있는데
**아이폰 시트 성공 갈래만 비어 있었다.** 시트가 닫히면 화면이 그대로라 «아무 일도 안
일어난» 모양이 된다. 실측의 「완료 안내를 보지 못했다」·「한 단계 더 골라야 한다」가
같은 구멍이었다.

문구는 **사실만** 말한다 — `navigator.share()` 는 사용자가 시트에서 무엇을 골랐는지
돌려주지 않아 「저장했어요」라고 쓰면 「복사」를 고른 사람에게 거짓이 된다. 그래서
「넘겼어요」에서 멈추고, 남은 한 단계를 덧붙인다.

> 사진을 공유 시트로 넘겼어요 — 시트에서 「이미지 저장」을 고르면 사진 앱에 들어가요.

시트를 그냥 닫은 경우(`cancelled`)에는 아무 말도 안 한다. 선택 모드는 그대로 둔다 —
취소했거나 「복사」를 고른 사람이 다시 누를 수 있어야 한다.
